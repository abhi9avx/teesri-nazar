Reports

Every run ends in a report you can share: what was tested, what passed, what failed and why, with a screenshot for every check.

Where to find it

Each run gets its own folder, runs/<run-name>/. The report is written when the run stops.

FileWhat it is
report.htmlThe report to share. Opens in any browser; screenshots are linked next to their checks.
report.mdThe same report in Markdown, ready to paste into a PR, Jira or Confluence.
ScreenshotsPNG evidence for every check, kept in the run folder. A failed or blocked case also gets its logcat, and a crash or ANR its crash log, linked as evidence.
events.jsonlEvery step as data. Replay reads this.

What it contains

  1. Header. The app and its version, the device and Android version, when it started and how long it took, and your original request.
  2. Summary. Cases passed, failed, blocked and skipped, and how many checks passed.
  3. Case table. Every case with its result, checks passed, and the reason it failed or was blocked. When available, the AI token cost of each case.
  4. Case details. Each check with what was expected and what was seen, notes, and screenshots. Within a case, the screenshots of failed checks come first, framed in red, so the problem is the first thing you see. Cases stay in run order.
  5. Crashes and ANRs. Caught automatically and attached to the case they happened in, with the log.
  6. Bugs found. Every bug the agent noted, with the case it came from.
  7. Navigation map. The routes goto used during the run, and whether each one arrived.
  8. Slow steps. Any step over 5 seconds, and why it was slow.

What each result means

ResultMeaning
✅ passEvery check in the case passed.
❌ failA check failed, or the app crashed or stopped responding.
⛔ blockedThe case could not run, for example the environment was down. The reason is recorded.
⏭ skippedOut of scope for this run.

Commands

./tnazar runs              # list recent runs
./tnazar report my-run     # rewrite a run's report
./tnazar replay my-run     # run it again and re-check every result

Before you share. Screenshots show exactly what the screen showed. Secrets typed with --env are never printed or logged, but a value typed into a plain (non-password) field is visible on screen, so check screenshots before sending a report outside your team.
