Quick start

Run your first AI-driven test on an Android phone or emulator in four steps.

Requirements

You needCheck it with
adb (Android platform-tools) on your PATH, or ANDROID_HOME setadb version
A phone with USB debugging allowed, or a running emulatoradb devices lists it
Python 3.9 or newer. Standard library only, nothing to installpython3 --version
Claude Codeclaude --version

Steps

  1. Get the code

    Clone the repository and open the folder.

    git clone https://github.com/abhi9avx/teesri-nazar.git
cd teesri-nazar

  2. Add your test data

    Secrets such as test PINs and OTPs go in .env; accounts, environment, DB and Figma links in testdata.yaml. Both are gitignored.

    cp .env.example .env
cp testdata.example.yaml testdata.yaml

  3. Connect a device

    Plug in a phone with USB debugging on, or start an emulator. It must show as device.

    adb devices

  4. Ask for a test

    Start Claude Code in the folder and describe the feature in your own words. It shows you the plan before it touches the phone.

    claude
› Open Settings and check that search finds Wi-Fi.

What you get

Every run is saved in runs/<name>/: the step log, screenshots and logs. report.html is the one to share. It lists each case as passed, failed or blocked, with what was seen against what was expected. See Reports.

Tip. Run ./tnazar ui in a second terminal to watch the phone and steer the agent while it tests. See Live dashboard.

What it costs

Teesri Nazar is free and open source under the MIT license. You need Claude Code, which needs a Claude subscription or API usage. When Claude drives a run, its report shows the tokens used per case, so you can see what a test costs. A saved plan runs with ./tnazar run and needs no model turn per step.
