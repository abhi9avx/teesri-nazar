Data and privacy

tnazar runs on your computer and sends nothing anywhere. The AI that drives it is Claude Code, which sends what it reads to Anthropic's model. This page says which is which.

What stays on your computer

  • Runs in runs/<name>/: the step log, screenshots, screen dumps, logs and the report. They stay until you delete them.
  • The learned app map and run state in .tnazar/.
  • Secrets and test data in .env and testdata.yaml. Both are gitignored.
  • The live dashboard listens on 127.0.0.1 only, needs a per-session token for every change, and serves files only from runs/.

tnazar has no telemetry, no account and no SDK inside your app. It talks only to your device, through adb.

What Claude Code sends to Anthropic

Claude Code sends what it reads to Anthropic's model so it can decide the next step. In a test run that is:

  • Your request, and any test cases, PRD text or links you give it.
  • The screen as text: each observe lists the elements on screen with their ids, labels and text. Any data shown on screen is in that text, so test with test accounts, not real customer data.
  • The output of the commands it runs, including the result of any DB query it runs for a check.
  • Screenshots are evidence for you. One is sent only when Claude opens it, as it does for a Figma comparison or replay --visual.

How long Anthropic keeps this, and whether it is used for training, depends on your Claude plan. See Claude Code data usage.

Secrets

  • PINs, OTPs and passwords are typed with type --env NAME. Claude sees only the name; the value is never printed, logged or recorded.
  • An OTP sent from the dashboard with Type it now goes straight to the device and never reaches the chat or the disk.
  • Values from .env are masked as •••• in printed output and saved screen dumps.
  • Screenshots show what the screen shows. A secret typed into a plain (non-password) field is visible in them. Secure screens (FLAG_SECURE), such as PIN entry, come out black.

Before you test a real app

  • Use a test environment and test accounts. Never point DB checks at production.
  • Keep runs/ out of shared drives and repos if screens can show personal data.
  • Check your Claude plan's data settings before sending screens of an internal app.
