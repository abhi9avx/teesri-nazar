Two ways to test a feature today. Both leave gaps.

Manual testing doesn’t repeat. Scripted automation arrives after the feature ships and breaks when the screen changes. An agent can do what the manual tester does, and leave behind something you can run again.

How the agent works a feature

Claude Code is the tester’s judgement. tnazar, a small Python tool, gives it eyes and hands on the phone and writes down everything it does.

  1. Look

    Reads the screen’s element tree: ids, labels, text, positions. About 0.05 seconds through the UiAutomator2 server.

    observe

  2. Act

    Taps, types and scrolls on the right element, found by its id, then its label, then its text. Never by guessing from a picture.

    tap "Pay now"

  3. Check

    Verifies every expected result on screen, and in the database or against Figma when you give it access.

    check "Payment successful"

  4. Record

    Saves each step with a screenshot, so the session becomes a report and a test you can replay.

    replay my-run

One agent plays the whole team

You say what to test. It switches hats as the work needs.

Senior QA
Turns your input into test cases and adds the edge cases nobody wrote down.
End user
Taps through the app on a real phone or emulator, like a customer would.
Developer
Catches crashes and ANRs as they happen and gives exact repro steps.
Product manager
Checks the build against the PRD and the Figma frame: is it what we promised?
Test lead
Hands you one report: what passed, what failed, what it saw, what it couldn’t test.

It learns your app as it tests

Every run maps the screens it walks through and the taps between them. Ask for a screen it has seen and it goes straight there, checking each step on the way. Money-moving steps are never replayed.

What the learned map does

Watch it, and steer it while it runs

./tnazar ui opens a live dashboard on your own machine: the phone screen, every step as it happens and a box to talk to the agent.

  • Send a message mid-run. The agent hears it within a second and changes course before its next tap.
  • Pause and resume. The next device step waits until you say so.
  • Hand over an OTP. The dashboard types it into the field itself. The value never reaches the chat, a log or the disk.
  • Stays local. It listens on 127.0.0.1 only. Nothing is uploaded.

Ten heads, one arrow

On Dussehra, the ten-headed Ravana burns. Every release has ten heads of its own, and two eyes rarely catch them all. The third eye looks at every screen, every time.

  1. Crash at ₹0
  2. ANR on a slow network
  3. Copy drifts from Figma
  4. Back skips a screen
  5. Double tap pays twice
  6. Spinner never ends
  7. Error says nothing
  8. Keyboard hides the button
  9. Dark mode unreadable
  10. Breaks on a small screen
