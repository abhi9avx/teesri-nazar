Watch one case run

It looks at each element before it touches it.

Every tap goes to an element found by its id, label or text. Every expected result is checked on screen, and a mismatch is caught, not skimmed past.

Every step, the same four moves

It looks before it taps, and checks before it says pass.

No coordinates guessed from a screenshot. Every element is found by its id, then its label, then its text, so the run survives a new build and a different screen size.

  1. 1

    Look

    Reads the screen’s element tree in about 0.05 s.

    tnazar observe
  2. 2

    Act

    Taps, types or scrolls on the right element.

    tnazar tap id=btn_pay
  3. 3

    Check

    Proves each expected result, with a screenshot.

    tnazar check "Paid" --for E1
  4. 4

    Record

    Saves the step so the whole run can be replayed.

    tnazar replay <run>

What changes for the team

The phone gets tapped. Your team gets its afternoon back.

Same app, same release train. What changes is who does the repetitive part.

You stop being the release’s fingers.

  • Tapping every case on every buildApproving a plan once, replaying it each release
  • Screenshots pasted into a sheetA screenshot for every check, in the report
  • Edge cases you happen to rememberEdge cases it adds: empty input, back mid-flow, kill and reopen
  • “Passed” because nothing looked wrongPassed only when every expected result was checked

Bugs arrive with steps, not screenshots of screenshots.

  • “Works on my phone”Exact repro steps, recorded and replayable
  • A crash a customer foundCrashes and ANRs fail the case on their own
  • Waiting a day for QA sign-offA run on the build you just pushed

Check the build against what you promised.

  • Comparing the app to Figma by eyeCopy and layout checked against the frame
  • “Is every requirement covered?”Each requirement traced to a check, or listed as not verified
  • A green tick nobody can explainPass, fail or blocked, each with its reason

What you get back

A report that says what it saw, not that it tried.

Every requested case shows up, including the ones that could not run. A failure comes with what was expected, what was on screen, and the screenshot.
